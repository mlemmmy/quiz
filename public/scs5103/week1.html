01

Pattern Recognition

The umbrella discipline — everything else this week is a piece inside it.

1. Definition

Academic: Pattern recognition is the scientific discipline concerned with the automatic discovery of regularities in data through algorithms, and the use of these regularities to take actions such as assigning the data to one of several categories.

Plain English: It's teaching a machine to notice a repeating shape, sound, or rule in data, and then use that noticing to make a decision — like sorting mail by handwritten zip code, or deciding a photo shows a cat and not a dog.

2. Keywords
Pattern — a regularity or structure in data Feature — a measurable property used to describe a pattern Feature vector — an ordered list of features for one item Class / category — the group a pattern is assigned to Classifier — the algorithm that assigns classes Training data Test data Supervised learning — learns from labeled examples Unsupervised learning — finds structure without labels Decision boundary — the line/surface separating classes Feature space Dimensionality — number of features Generalization — performing well on unseen data Overfitting — memorizing training data instead of learning the rule Noise Ground truth Preprocessing
3. Core explanation

What is it? A field that sits between statistics, computer science, and signal processing, all aimed at one question: given raw measurements, which category do they belong to?

What does it mean? Real-world objects — a face, a signature, a tumor on a scan — rarely repeat identically. Pattern recognition assumes that despite variation, members of the same class share statistical regularities that can be measured and learned.

Purpose: to automate decisions that would otherwise need a human expert looking at each item one by one.

Why it matters: almost every modern "smart" system — unlocking a phone by face, a spam filter, a doctor's diagnostic aid — is a pattern recognition system underneath.

Problem it solves: humans are slow, inconsistent, and don't scale. A trained system can process millions of items with a repeatable, tunable decision rule.

4. How it works
  1. Sensing: a sensor captures raw data (camera, microphone, scanner).
  2. Preprocessing: noise is reduced, signal is normalized.
  3. Feature extraction: the raw data is turned into a compact, informative set of numbers.
  4. Classification: a decision rule maps the feature vector to a class.
  5. Output: the system reports a decision (and often a confidence score).
5. Diagram

Each stage narrows raw, noisy input down to a single decision — the whole point is compression: from a huge signal to one label.

6. Example

A postal sorting machine photographs a handwritten zip code, extracts the shape of each digit, and classifies each one as 0–9 — no human reads it.

A phone camera detects a face in the frame and recognizes whose face it is, comparing it against stored templates.

7. Applications
  • Biometrics: fingerprint, face, and iris recognition for identity.
  • Medicine: classifying tumors as benign/malignant from scans.
  • OCR: reading printed or handwritten text.
  • Speech: recognizing spoken words or a speaker's identity.
  • Industry: detecting defective parts on a production line.
  • Finance: flagging fraudulent transactions.
8. Advantages
  • Speed: decisions in milliseconds at scale.
  • Consistency: the same input always gets the same treatment, unlike a tired human.
  • Handles large data: can sift through volumes no human team could review.
  • Finds subtle regularities: can pick up patterns too faint or high-dimensional for a person to notice.
9. Limitations
  • Data-dependent: poor or biased data produces poor or biased decisions.
  • Sensitive to noise: corrupted measurements can mislead the classifier.
  • Generalization risk: a system tuned too closely to training data can fail on new data (overfitting).
  • Opacity: some classifiers (e.g. neural networks) are hard to interpret.
10. Comparisons
Pattern RecognitionImage ProcessingMachine Learning
GoalAssign a category to inputTransform/enhance an imageLearn a function from data generally
OutputA class labelA modified imagePredictions of any kind
RelationshipOften uses image processing as its preprocessing stepProvides many of the algorithms pattern recognition uses

Common confusion: Pattern recognition is often treated as a synonym for machine learning — in reality, pattern recognition is the older, application-focused field (specifically about classification/description of patterns); machine learning is the broader set of learning algorithms it draws on.

11. Mathematical / formula component

A pattern is represented as a feature vector x = [x₁, x₂, …, xd], a point in a d-dimensional feature space. No further formal mathematics is needed yet — this notation is simply the language every later concept will build on.

MEMORY ANCHOR"Measure it, describe it, decide it." Every pattern recognition system does exactly those three things, in that order.
MUST REMEMBER
  1. Pattern recognition = automatically discovering regularities in data and using them to classify.
  2. Pipeline: sensing → preprocessing → feature extraction → classification → decision.
  3. A feature vector is the numeric description of one pattern.
  4. It underlies biometrics, medical diagnosis, OCR, speech recognition, and fraud detection.
  5. Machine learning supplies the algorithms; pattern recognition is the applied discipline that uses them for classification/description.

02

Measured Patterns

Builds on Pattern Recognition — before you can classify anything, you need actual measurements to work with.

1. Definition

Academic: A measured pattern is the set of quantitative or qualitative measurements taken from a real-world object or phenomenon through sensing and transduction, forming the raw input to a pattern recognition system.

Plain English: It's the actual numbers you get by measuring something — a fingerprint's ridge spacing, a photo's pixel brightness values, a patient's temperature — before any pattern-finding has happened.

2. Keywords
MeasurementSensorTransducer Raw data / signalAttribute / variable Nominal scale — labels, no order (e.g. blood type) Ordinal scale — ordered categories (e.g. mild/moderate/severe) Interval scale — ordered, equal spacing, no true zero Ratio scale — ordered, equal spacing, true zero Continuous variableDiscrete variable SamplingResolutionCalibration DigitizationNoise
3. Core explanation

What is it? The measurement stage is where the physical world gets converted into numbers a computer can process.

What does it mean? Every pattern recognition system starts from something physical — light, sound, pressure, temperature — that a sensor converts into a signal.

Purpose: to give the system a faithful, numeric description it can compare across many examples.

Why it matters: the whole system is only as good as its measurements — poor sensors or poor calibration put a ceiling on accuracy no algorithm can fix later.

Problem it solves: raw physical phenomena aren't directly computable; measurement bridges the physical world and the digital pipeline.

4. How it works
  1. Phenomenon: the real-world object or event (e.g. a finger touching a scanner).
  2. Transduction: a sensor converts a physical quantity into an electrical signal.
  3. Sampling/digitization: the continuous signal is sampled at discrete points and converted to digital values.
  4. Measurement vector: the digitized readings are organized into a structured record.
5. Diagram 
Physical Phenomenon (light, sound, pressure...)

6. Example

A fingerprint scanner measures ridge positions and pressure at thousands of points on a finger. A digital camera measures light intensity at every pixel. A hospital monitor measures heart rate, blood pressure, and oxygen saturation.

7. Applications
  • Medical devices: vitals monitoring feeding diagnostic systems.
  • Biometric scanners: capturing fingerprint, iris, or voice signals.
  • Remote sensing: satellites measuring reflected light for land classification.
  • Industrial sensors: measuring vibration or temperature to detect faults.
8. Advantages
  • Objectivity: numeric measurement removes subjective judgment.
  • Reproducibility: the same phenomenon can be re-measured and compared over time.
  • Foundation for automation: once digitized, data can be processed at any scale.
9. Limitations
  • Sensor noise: imperfect sensors introduce error.
  • Calibration drift: sensors can lose accuracy over time.
  • Limited resolution: some measurements can't capture fine detail.
  • Cost: precise sensing equipment can be expensive.
10. Comparisons
Measured Pattern (raw)Feature
StageStraight from the sensorAfter processing/selection
VolumeOften large, redundantCompact, informative
ExampleEvery pixel value in an imageEdge count, average intensity

Common confusion: students often use "measurement" and "feature" interchangeably. A measurement is raw; a feature is a deliberately chosen or computed property that is useful for distinguishing classes.

11. Mathematical / formula component

A measured pattern is represented as a vector of raw readings: x = [x₁, x₂, …, xn], where each xi is one sensor reading. Example: a blood pressure reading might be x = [120, 80] (systolic, diastolic) — two raw measurements, no interpretation yet.

MEMORY ANCHOR"Measurement is the world becoming numbers." Nothing else in the pipeline can happen until this step exists.
MUST REMEMBER
  1. A measured pattern is raw, sensor-derived data — before feature extraction.
  2. Sensors/transducers convert physical phenomena into signals; sampling digitizes them.
  3. Measurement scales: nominal, ordinal, interval, ratio.
  4. Measurement quality (noise, calibration, resolution) puts a ceiling on system accuracy.
  5. Measured pattern ≠ feature: features are derived from measurements.

03

Classes

Builds on Measured Patterns — once you can measure a pattern, you need buckets to sort it into.

1. Definition

Academic: A class (or category) is a set of patterns that share common statistical or structural characteristics, defined so that a classification system can assign new patterns to it based on a decision rule.

Plain English: A class is a labeled bucket — "cat," "dog," "spam," "benign tumor" — that things get sorted into once you know their measurements.

2. Keywords
Class / categoryLabelClass boundary Within-class variability — differences among members of the same class Between-class variability — differences that separate classes Binary (two-class)Multi-class Prior probability — how likely a class is before seeing any data Class-conditional density — distribution of features given a class Discriminant functionGround truth label Class imbalanceCluster (unsupervised analog)
3. Core explanation

What is it? The set of possible answers a classifier can give.

What does it mean? Defining classes is a design decision — a system must be told in advance what categories exist (in supervised settings) before it can learn to tell them apart.

Purpose: to give structure to the problem; without defined classes, "classification" has no target.

Why it matters: the quality of class definitions directly affects how learnable the problem is — poorly defined, overlapping classes make even a perfect algorithm struggle.

Problem it solves: converts an open-ended recognition problem into a closed decision among a known set of outcomes.

4. How it works
  1. Define classes: decide, from domain knowledge, what categories exist (e.g. digits 0–9).
  2. Collect labeled examples: gather patterns whose true class is known.
  3. Characterize each class: examine how its feature values are distributed.
  4. Locate class regions: in feature space, each class ideally occupies its own region.
5. Diagram 
Feature 2
   │        o o
   │      o  o  o     Class A (o)
   │        o o
   │
   │                x x
   │              x  x  x   Class B (x)
   │                x x
   └──────────────────────── Feature 1

Each class occupies a region of feature space. Classification later works by figuring out which region a new point falls into.

6. Example

In handwritten digit recognition, the classes are "0" through "9." In medical diagnosis, the classes might be "benign" and "malignant." In animal recognition, classes could be "cat," "dog," "bird."

7. Applications
  • Spam filtering: classes are "spam" and "not spam."
  • Medical screening: classes such as disease-present / disease-absent.
  • Species identification: classes correspond to species.
  • Biometric identification: each enrolled person is effectively their own class.
8. Advantages
  • Clarity of goal: well-defined classes give the whole system a clear target.
  • Enables evaluation: known classes let you measure accuracy against ground truth.
  • Domain alignment: classes can be chosen to match real decisions people need (e.g. treat/don't treat).
9. Limitations
  • Overlapping classes: real classes often share feature space, causing ambiguous cases.
  • Class imbalance: some classes may have far fewer examples, biasing the classifier.
  • Subjectivity in definition: where to draw class boundaries isn't always obvious (e.g. "mild" vs "moderate" disease).
10. Comparisons
ClassCluster
OriginPredefined by a human/domain expertDiscovered automatically from data
Learning typeSupervisedUnsupervised
Label available?Yes, during trainingNo — labels are not given

Common confusion: "class" and "cluster" are often used loosely as synonyms; a class is known and labeled in advance, a cluster is a group the algorithm finds on its own.

11. Mathematical / formula component

Each class ωi has a prior probability P(ωi) — how common that class is overall. Example: if 1 in 100 scans shows a tumor, P(malignant) = 0.01 and P(benign) = 0.99. This single number becomes important later when weighing decisions under uncertainty.

MEMORY ANCHOR"A class is a bucket someone already labeled; a cluster is a bucket the machine found by itself."
MUST REMEMBER
  1. A class is a predefined category patterns can be assigned to.
  2. Classes ideally occupy distinct regions of feature space.
  3. Within-class variability vs between-class variability determines how separable classes are.
  4. Prior probability P(ωi) reflects how common a class is.
  5. Classes (supervised, labeled) differ from clusters (unsupervised, discovered).

A: Within-class = differences among members of one class; between-class = differences that separate classes from each other.

A: The probability of a class occurring before any measurement is considered, P(ωi).

04

Classification

Builds on Classes — now that buckets exist, this is the act of putting a pattern into the right one.

1. Definition

Academic: Classification is the process of assigning a pattern, represented by its feature vector, to one of several predefined classes based on a decision rule learned or derived from data.

Plain English: It's deciding which labeled bucket a new item belongs to, based on its measured features.

2. Keywords
ClassifierDecision ruleDecision boundary Discriminant functionSupervised learning Training setTest setFeature space Linear classifier — separates classes with a straight line/plane Nonlinear classifier — separates classes with a curved boundary Bayes classifierNearest neighbor Decision treeConfusion matrix Accuracy / error rateGeneralization
3. Core explanation

What is it? The decision-making core of a pattern recognition system.

What does it mean? A classifier is a function that takes a feature vector as input and outputs a class label.

Purpose: to automate the "which bucket does this belong in" decision, consistently and at scale.

Why it matters: this is the step that actually produces the useful output — everything before it (measuring, extracting features) exists to make this step possible.

Problem it solves: lets a system make a repeatable decision under uncertainty, rather than requiring exact matches to known examples.

4. How it works
  1. Training: the classifier learns a decision rule from labeled feature vectors.
  2. Decision boundary formation: the rule effectively draws a boundary separating classes in feature space.
  3. Inference: a new, unlabeled feature vector is compared against the learned rule.
  4. Output: the class on whichever side of the boundary the new point falls is returned as the decision.
5. Diagram 
Feature 2
   │      o o
   │    o  o  o   │
   │      o o     │  ← decision boundary
   │               │
   │               │   x x
   │               │ x  x  x
   │               │   x x
   └──────────────────────────── Feature 1

  New point ●  → falls left of boundary → classified as "o"
6. Example

A handwriting recognizer takes the stroke shape of a digit and classifies it as "7" rather than "1." A medical classifier takes a tumor's size, shape, and texture and classifies it as "benign" or "malignant."

7. Applications
  • Email filtering: classifying messages as spam or not.
  • Diagnostics: classifying scans or lab results as normal/abnormal.
  • Speech: classifying audio segments as specific words.
  • Quality control: classifying manufactured parts as pass/fail.
8. Advantages
  • Automates expert judgment: replicates decisions a human expert would make, at scale.
  • Quantifiable performance: accuracy, error rate, and confusion matrices let you measure and improve it.
  • Adaptable: retraining on new data lets the classifier improve over time.
9. Limitations
  • Boundary errors: points near the decision boundary are prone to misclassification.
  • Depends on feature quality: a classifier can't separate classes on features that don't actually differ between them.
  • Overfitting risk: an overly complex boundary may fit training noise rather than the true pattern.
10. Comparisons
ClassificationRegressionClustering
OutputA discrete class labelA continuous numberGroupings (no predefined labels)
Learning typeSupervisedSupervisedUnsupervised
ExampleSpam / not spamPredicted house priceCustomer segments

Common confusion: classification and regression are both "supervised," but classification predicts a category, while regression predicts a numeric quantity.

11. Mathematical / formula component

A simple decision rule using discriminant functions: for each class ωi, compute a score gi(x). Assign x to class ωi if gi(x) > gj(x) for all other classes j.

Meaning: each class "votes" with a score based on the input's features; the class with the highest score wins. Example: if g₁(x) = 7.2 and g₂(x) = 3.5, the pattern is assigned to class 1.

MEMORY ANCHOR"Classification is the vote-counting step — every class scores the input, and the highest score wins."
MUST REMEMBER
  1. Classification assigns a feature vector to one predefined class using a decision rule.
  2. The classifier is trained on labeled data, then applied ("inference") to new data.
  3. A decision boundary is the geometric expression of the classifier's rule.
  4. Discriminant functions gi(x) let classes "compete" for the highest score.
  5. Classification (discrete output) differs from regression (continuous output).

A: Assigning a feature vector to one of several predefined classes using a learned decision rule.

A: The surface in feature space that separates one class's region from another's.
tap

A: A function gi(x) that scores how strongly a feature vector belongs to class i; the highest-scoring class is chosen.
tap

A: They are close to being equally likely under either class, so small noise can flip the decision.
05

Steps Associated with Classification

Builds on Classification — this zooms out from the decision itself to the full pipeline around it.

1. Definition

Academic: The steps of classification are the sequential stages — from raw data acquisition through preprocessing, feature extraction, training, decision-making, and evaluation — that together constitute a complete pattern recognition system.

Plain English: It's the full recipe, start to finish, that turns a raw signal into a trustworthy class decision.

2. Keywords
Data acquisitionPreprocessingSegmentation Feature extractionFeature selection Dimensionality reductionTraining phase Model selectionTesting phaseEvaluation Cross-validationConfusion matrix OverfittingUnderfittingPost-processing
3. Core explanation

What is it? A structured pipeline, not a single algorithm — classification is the output of many coordinated stages.

What does it mean? Each stage transforms the data further, and errors introduced early (e.g. bad preprocessing) propagate through every later stage.

Purpose: to break an otherwise overwhelming problem (raw signal → decision) into manageable, testable steps.

Why it matters: understanding the pipeline lets you diagnose where a system is failing — is it the sensor, the features, or the classifier itself?

Problem it solves: provides a repeatable engineering process for building any pattern recognition system, regardless of domain.

4. How it works
  1. Data acquisition: collect raw samples via sensors.
  2. Preprocessing: remove noise, normalize scale, correct for missing values.
  3. Segmentation: isolate the object of interest from background (e.g. separating a face from the rest of a photo).
  4. Feature extraction: compute informative measurements from the segmented data.
  5. Feature selection / dimensionality reduction: keep only the most useful features, discard redundant ones.
  6. Training: fit a classifier on labeled examples (the training set).
  7. Testing / classification: apply the trained classifier to new, unseen data.
  8. Evaluation: measure accuracy/error using metrics like a confusion matrix; refine if needed.

6. Example

Fingerprint recognition end-to-end: (1) a scanner captures the finger image, (2) the image is cleaned of smudges and normalized, (3) the ridge pattern is segmented from the background, (4) minutiae points (ridge endings, bifurcations) are extracted as features, (5) the most distinctive minutiae are kept, (6) the system is trained on many enrolled fingerprints, (7) a new scan is compared against stored templates, (8) the match rate is evaluated to tune thresholds.

7. Applications
  • Any deployed recognition system — face ID, medical imaging AI, speech assistants — follows this same staged pipeline.
  • Industrial inspection systems use it to move from a camera image to a pass/fail decision.
  • Document processing systems use it to move from a scanned page to extracted, classified text.
8. Advantages
  • Modularity: each stage can be improved or swapped independently.
  • Debuggability: performance problems can be traced to a specific stage.
  • Reusability: the same pipeline structure applies across very different domains.
9. Limitations
  • Error propagation: a mistake in an early stage (e.g. bad segmentation) corrupts every later stage.
  • Complexity: more stages mean more places for something to go wrong and more to tune.
  • Train/test mismatch: if training data doesn't represent real-world conditions, testing performance can mislead.
10. Comparisons

Common confusion: students often conflate "feature extraction" with "feature selection" — extraction computes new measurements, selection chooses which of them to keep.

11. Mathematical / formula component

Data is commonly split into a training set and a test set, e.g. 70%/30% or 80%/20%. This is not a rigid law — it is a practical convention to check generalization. No further formal mathematics is essential at this foundational stage.

MEMORY ANCHOR"Acquire → Clean → Isolate → Describe → Trim → Train → Test → Judge." Eight verbs, eight stages.
MUST REMEMBER
  1. The 8 stages: acquisition, preprocessing, segmentation, feature extraction, feature selection, training, testing, evaluation.
  2. Errors early in the pipeline propagate to every later stage.
  3. Training uses labeled data to learn the rule; testing applies it to unseen data.
  4. Feature extraction computes new measurements; feature selection chooses among them.
  5. Evaluation (e.g. confusion matrix) closes the loop and drives refinement.

Biometrics

Builds on all five prior concepts — biometrics is a complete, real-world application of the whole pipeline.

1. Definition

Academic: Biometrics is the automated recognition of individuals based on their physiological and/or behavioral characteristics, applying pattern recognition and classification techniques to identity verification and identification.

Plain English: It's using your body or behavior — fingerprint, face, iris, voice, gait — as your ID, instead of a password or a card.

2. Keywords
Physiological biometric — fingerprint, face, iris, DNA Behavioral biometric — gait, signature, typing rhythm, voice EnrollmentTemplate Verification (1:1) — "are you who you claim?" Identification (1:N) — "who are you, among everyone enrolled?" Matching score FAR — False Acceptance Rate FRR — False Rejection Rate EER — Equal Error Rate Liveness detectionSpoofing UniquenessPermanenceUniversalityCollectability
3. Core explanation

What is it? The direct, everyday application of everything covered this week: measuring a body/behavior trait, extracting features, and classifying against enrolled identities.

What does it mean? A good biometric trait should be universal (everyone has it), unique (differs enough between people), permanent (stable over time), and collectable (practical to measure).

Purpose: to confirm or determine identity without relying on something a person can forget, lose, or lend to someone else (like a password or key card).

Why it matters: biometrics underpin phone unlocking, border control, banking security, and forensics.

Problem it solves: passwords and cards can be stolen or shared; biometric traits are tied directly to the individual.

4. How it works
  1. Enrollment: a trait is measured and its features are extracted and stored as a template.
  2. Capture: at recognition time, the trait is measured again.
  3. Feature extraction: the new capture is converted into a feature vector the same way as during enrollment.
  4. Matching: the new feature vector is compared to stored template(s), producing a matching score.
  5. Decision: if verifying, the system accepts/rejects against one claimed identity; if identifying, it searches all templates for the best match.
5. Diagram 
ENROLLMENT                      RECOGNITION
Trait ──► Feature ──► Template   Trait ──► Feature ──► Query vector
              │  (stored)                                  │
              └──────────────────► Matching ◄───────────────┘
                                      │
                              Verification (1:1)   or   Identification (1:N)
                                      │
                                  Accept / Reject / Identity
6. Example

Unlocking a phone with Face ID: your face was enrolled once as a template; each unlock attempt captures your face again and checks it matches (verification, 1:1).

An airport border system that identifies a traveler against a watchlist of thousands of faces is doing identification (1:N) rather than verification.

7. Applications
  • Consumer devices: fingerprint/face unlock on phones and laptops.
  • Border control: passport e-gates using face or iris recognition.
  • Banking: voice or fingerprint authentication for transactions.
  • Forensics: matching fingerprints or DNA to crime scene evidence.
  • Attendance/access systems: workplace entry via fingerprint or face.
8. Advantages
  • Hard to lose or share: unlike a password, you always "have" your fingerprint or face.
  • Convenience: nothing to remember or carry.
  • Strong link to identity: harder to impersonate than knowledge-based credentials.
9. Limitations
  • Privacy concerns: biometric data is sensitive and, unlike a password, can't be "reset" if compromised.
  • Spoofing risk: photos, fake fingerprints, or recordings can attempt to fool a system without liveness detection.
  • Trait changes over time: injuries, aging, or illness can alter a trait and increase false rejections.
  • Cost and infrastructure: high-quality sensors and matching systems can be expensive to deploy.

Common confusion: verification and identification are often used interchangeably, but they are different matching problems — one comparison vs. a search across many.

11. Mathematical / formula component

False Acceptance Rate (FAR): the proportion of impostor attempts wrongly accepted. False Rejection Rate (FRR): the proportion of genuine attempts wrongly rejected. The Equal Error Rate (EER) is the point where FAR = FRR — a common single-number summary of a biometric system's accuracy. Lower EER means a more accurate system.

MEMORY ANCHOR"Enroll once, match every time." Biometrics is the classification pipeline running against a single question: does this match a stored template?
MUST REMEMBER
  1. Biometrics = identity recognition from physiological or behavioral traits.
  2. Pipeline: enrollment → capture → feature extraction → matching → decision.
  3. Verification is 1:1 ("are you who you claim?"); identification is 1:N ("who are you?").
  4. A good trait is universal, unique, permanent, and collectable.
  5. FAR, FRR, and EER quantify a biometric system's accuracy.

Q: Define biometrics.
A: Automated recognition of individuals based on physiological/behavioral traits, using pattern recognition and classification.

Q: Verification vs identification — what's the difference?
A: Verification is a 1:1 check against a claimed identity; identification is a 1:N search across all enrolled identities.

Q: Give two examples each of physiological and behavioral biometrics.
A: Physiological: fingerprint, face/iris/DNA. Behavioral: gait, signature/typing rhythm/voice.

Q: What do FAR and FRR measure?
A: FAR = rate of wrongly accepting impostors; FRR = rate of wrongly rejecting genuine users.

Q: What is the Equal Error Rate (EER)?
A: The point where FAR equals FRR — a single-number summary of biometric system accuracy; lower is better.

Q: Why is biometric data considered higher-risk than a password if compromised?
A: Unlike a password, a biometric trait cannot be "reset" once its data is stolen.
